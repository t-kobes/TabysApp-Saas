> Документ для внешней оценки. Самодостаточный: контекст, текущее состояние, готовность, риски, план выхода.

---

## TL;DR

**Табыс** — Telegram-платформа сервисов для продавцов маркетплейсов Казахстана (Kaspi, Wildberries, Ozon). Формат: Telegram Mini App (TMA) + бот-консьерж. Стадия: **pre-revenue, ~4 пользователя, ранний продукт**.

Готов и работает в проде **клин-продукт** — кроссплатформенный калькулятор маржи со сравнением Kaspi vs WB на одном экране (позиция, которой нет ни у одного конкурента в КЗ), история расчётов, авторизация через Telegram, бот, который заводит людей в приложение. Хостинг — **$0/мес** (Vercel + Supabase free tier).

Из ~18 заявленных в видении сервисов в проде **1** (≈6%), но под ним выстроен серьёзный фундамент (идентичность, данные с RLS, воронка, сбор спроса). Решение по выходу: добрать **3–4 живых бесплатных инструмента (~35–40%)** и звать первую волну пользователей по модели «бесплатно за честный отзыв».

## 1. Продукт

**Проблема.** Продавцы КЗ торгуют на Kaspi и Wildberries одновременно, но не знают реальную маржу — не учитывают комиссии площадок, логистику, курс закупки. Узнают, что работали в минус, постфактум. Считают в Excel или в уме.

**Решение.** Открыл Telegram → один тап → за 30 секунд видишь реальную прибыль и ROI на каждой площадке и где выгоднее продавать. Без регистрации, установки, обучения.

**Дифференциатор.** Единственный инструмент в КЗ, который **сравнивает маржу Kaspi vs WB в одном экране**. Конкуренты (SellStat, SaleScout, AlgaTop) работают с одной площадкой; МойСклад — дорогой ERP. Кросс-платформенное сравнение — незанятая позиция.

**Аудитория.** Малые продавцы: оборот 0.5–5 млн ₸/мес, 10–200 SKU, 1–3 площадки, основной мессенджер — Telegram. Вторично — начинающие («стоит ли вообще выходить»).

**Бизнес-модель (план).** Free (калькуляторы, сравнение — навсегда) → Standard 2 490 ₸/мес (SEO, валюта, налоги) → Pro 4 990 ₸/мес (аналитика, радар). Сейчас **всё бесплатно** до зрелости функционала; монетизация только после D7-retention > 20%.

## 3. Что построено и работает в проде

**Telegram Mini App (Vercel):**
- **Дом-лаунчер** — сетка инструментов, приветствие по имени, тариф-карточка, проф. UI (иконки, дисклеймер, метка `beta`).
- **Калькулятор маржи** — один ввод (закуп, продажа, категория, вес) → результат по **Kaspi и WB одновременно** + вердикт «где выгоднее на N ₸». Кнопка «поделиться».
- **История расчётов** — все прошлые сравнения пользователя (под RLS — только свои).
- **Fake Door** — плитки будущих сервисов («Скоро»/«Pro») со сбором реального интереса в БД (тест спроса).

**Авторизация:**
- Edge Function проверяет подпись Telegram `initData` (HMAC) и выдаёт JWT. Полноценная сессия, у каждого свои данные. Не доверяет клиенту.

**Бот-консьерж (Telegram webhook на Edge Function):**
- `/start` → приветствие + вопрос «главная боль?» с 4 кнопками (сегментация). Любое сообщение → короткая AI-консультация (Gemini). Всегда заводит в приложение. Калькулятор из бота убран — единый источник правды это TMA.

## 4. Архитектура (текущая)

| Слой | Решение | Статус |
|---|---|---|
| Frontend (TMA) | React + Vite + TS + Tailwind | live на Vercel |
| Backend-логика | Supabase Edge Functions (Deno): `tg-auth`, `bot` | live |
| БД | Supabase Postgres + RLS (по `telegram_id` из JWT) | live |
| LLM | Google Gemini (консультация бота, SEO) | live |
| Бот | Telegram Bot API через webhook | live |
| Прежний NestJS-бэкенд | ретайрнут (код в репо, не запущен) | off |

Ключевое архитектурное решение — **TMA-first**: вся динамика на Supabase, TMA ходит в БД напрямую под RLS. Это даёт **always-on за $0** (нет всегда-включённого сервера) и убирает операционную нагрузку для команды из одного человека.

## 6. Ключевые продуктовые решения

- **TMA-first, бот = консьерж.** Единый источник правды — приложение; бот только заводит в него. Снимает дублирование логики и нагрузку хостинга.
- **Бесплатно за честный отзыв.** Платных гейтов нет до зрелости функционала; монетизация после D7 > 20%.
- **Онбординг = только имя** (берётся из Telegram), профиль — после первого расчёта. Приоритет активации над данными.
- **Fake Doors как тест спроса** — будущие сервисы показываются плитками, тапы пишутся в БД; что строить дальше, решают пользователи.

## 7. Риски и ограничения (честно)

- ⚠️ **Ставки комиссий/логистики WB — заглушки** (приблизительные). Сравнение Kaspi·WB сейчас на условных числах WB — заменить реальными до приглашения юзеров. Kaspi — реальные.
- **До-трекшен:** ключевая гипотеза (нужно кросс-сравнение) количественно не подтверждена. Первая волна — её проверка.
- **Команда из одного человека** — пропускная способность ограничена; отсюда выбор «не строить вслепую».
- **Ozon не покрыт** (заявлен в видении, в калькуляторе пока Kaspi+WB).
- **Технический долг (мелкий):** JWT в TMA хранится в `localStorage` — на iOS Telegram может его чистить; при жалобах на разлогин — переезд на `CloudStorage`.

## 8. План выхода (GTM)

Решение: **не ждать 60–70% сервисов** (это противоречит Fake-Door-логике и риску строить не то), а добрать ядро до «не пусто» и звать рано.

- **Сейчас:** ядро (маржа + сравнение + история) готово.
- **Нед. 1–2:** 3 живых инструмента — валютный, налоговый, SEO-в-TMA → free ощущается полным (4–5 инструментов, ~35–40%).
- **Волна 1 (~конец июня):** 10–20 знакомых селлеров лично, «тестируем вместе, нужен честный отзыв». Метрики: активация (сделал расчёт?), возврат **D1/D7**, голоса Fake Door.
- **Июль:** строим топ-2–3 сервиса по голосам/фидбеку → **Волна 2** (TG-канал: реальные разборы маржи + скрины).
- **Монетизация:** после стабильного D7 > 20%.
